How to remove leftover files after uninstalling Mac apps

Trash removes the .app — not Library leftovers. Match by bundle ID, review helpers carefully, prefer Trash over rm

Updated 2026-09-14

Dragging an app to Trash deletes the bundle under /Applications (or ~/Applications). Preferences, caches, sandbox containers, logs, and sometimes launch agents stay behind under ~/Library. The safe loop is: vendor uninstaller first when it exists, quit the app, record the bundle ID, then review matching Library paths and move confirmed leftovers to Trash. Do not disable SIP. Do not delete under /System or /usr.

Vendor uninstaller first

Apps with drivers, network extensions, privileged helpers, or license daemons often ship their own Uninstall tool (common for VPNs, antivirus, audio plugins, Adobe, Microsoft, and similar suites). Run that before any manual Library walk. File deletion alone is a poor substitute for tearing down registered extensions.

If you installed via Homebrew Cask, prefer brew uninstall --cask … over trashing the bundle so receipts stay consistent. App Store apps can be removed from Launchpad or Applications; leftovers in ~/Library may still remain.

Quit, then capture the bundle ID

Fully quit the app and any visible helpers. While the .app still exists, note its identity:

  • Right-click the app → Show Package Contents → open Contents/Info.plist.
  • Copy CFBundleIdentifier (looks like com.vendor.product).
  • Also note the developer / company name used in folder names under Application Support.

Bundle ID beats display name. Name-only matches are weaker and more likely to collide with similarly named apps. If the app is already gone and you never saved the ID, search carefully by developer name and leave ambiguous hits alone.

Where leftovers usually live

In Finder, use Go → Go to Folder… (⇧⌘G) and open ~/Library. Search each of these trees for the bundle ID or developer folder name:

zsh — common leftover roots
# user Library (most leftovers)
$ open ~/Library/Application\ Support
$ open ~/Library/Caches
$ open ~/Library/Preferences
$ open ~/Library/Containers
$ open ~/Library/Group\ Containers
$ open ~/Library/Logs
$ open ~/Library/Saved\ Application\ State
$ open ~/Library/LaunchAgents
# optional size check once you know a path
$ du -sh ~/Library/Application\ Support/VENDOR_OR_APP

Also check ~/Library/WebKit, ~/Library/HTTPStorages, and crash reports when the app was Electron-heavy or crashy. Prefer moving confirmed items to Trash over rm -rf so you can restore a mistake.

Shared containers and weak matches

Sandboxed apps often use ~/Library/Containers/<bundle-id> — those are usually attributable. Group Containers and vendor-named Application Support folders can be shared across several apps from the same developer. If another product from that vendor is still installed, leave the shared folder alone.

Preferences named com.vendor.product.plist are strong matches. Folders that only vaguely resemble a display name are weak matches — skip them unless you recognize the contents.

Launch agents and privileged helpers

Background leftovers often live in:

  • ~/Library/LaunchAgents — user agents (usually removable after review)
  • /Library/LaunchAgents and /Library/LaunchDaemons — system-wide; admin rights
  • /Library/PrivilegedHelperTools — root helpers paired with daemons

Check System Settings → General → Login Items & Extensions for orphaned login items or background tasks pointing at a missing path. Prefer the vendor uninstaller for helpers and extensions. Do not casually delete under /Library without recognizing the exact helper name and plist.

Review checklist

  • Do first: vendor uninstaller / brew uninstall --cask when applicable; quit the app.
  • Strong matches: paths and plists that include the exact bundle ID.
  • Review carefully: Group Containers, vendor Application Support shared by multiple apps, LaunchDaemons, PrivilegedHelperTools.
  • Leave alone: Keychain items you still need, iCloud documents, other apps’ data, anything under /System or /usr.
  • Never: SIP off, blind rm -rf ~/Library, or deleting folders you cannot attribute.

After moving confirmed leftovers to Trash, use the Mac normally for a bit, then empty Trash when you are sure. Space returns when Trash is emptied, not when files first move there.

Frequently asked questions

Does moving a Mac app to Trash uninstall it completely?
No. Trash removes the .app bundle. Preferences, caches, containers, logs, and sometimes launch agents often remain under ~/Library (and occasionally /Library for privileged helpers).
How do I find leftovers after the app is already gone?
Search ~/Library by the former bundle ID (com.vendor.product) or the developer name. Without that identity, name-only matches are weaker — leave uncertain folders alone.
Do I need to disable SIP to remove app leftovers?
No. Ordinary leftovers live under your home Library. Do not disable SIP and do not delete anything under /System or /usr. Treat /Library helpers with extra caution and prefer vendor uninstallers.
