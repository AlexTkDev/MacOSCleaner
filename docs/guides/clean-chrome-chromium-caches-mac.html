Clear Chrome and Chromium caches on Mac without losing logins

Measure the cache and profile folders first, clear only cached files from the browser itself, and keep cookies, saved passwords and history where they are

Updated 2026-10-15

Chrome splits its files between two places on a Mac. The disk cache sits in ~/Library/Caches/Google/Chrome, and your actual profile (bookmarks, history, saved passwords, cookies, extensions) sits in ~/Library/Application Support/Google/Chrome. Only the first one, plus a few cache subfolders inside the second, is safe to throw away. The safe loop is: measure both folders with du, clear Cached images and files from Chrome’s own Delete browsing data dialog in each profile, and use Finder only for cache folders you have identified by name. Never delete the whole Chrome folder in Application Support, never clear cookies as a “cleanup” step, and never reach for sudo rm.

Why Chrome shows up as System Data or “Other”

macOS storage settings don’t have a “browser” bar. Files under ~/Library that don’t belong to Apps, Documents, Photos and similar buckets are usually counted under System Data (called Other on older macOS versions). Browser caches and profiles live in ~/Library, so a heavy Chrome setup quietly adds to that grey bar.

Chromium-based browsers on macOS follow one rule: if a profile lives under ~/Library/Application Support/<browser>/<profile>, its disk cache goes to the matching path under ~/Library/Caches/<browser>/<profile>. That is why Chrome’s cache for the Default profile ends up in ~/Library/Caches/Google/Chrome/Default, while its cookies and history stay in Application Support.

Cache also grows back: by default Chrome picks its cache size itself, based on free disk space, so clearing it is a one-time reclaim, not a permanent saving.

Measure first (read only)

These commands only read sizes. Run them before changing anything, so you know whether Chrome is the problem and which folder is heavy.

zsh — measure (read only)
$ du -sh ~/Library/Caches/Google/Chrome
$ du -sh ~/Library/Application\ Support/Google/Chrome
# per profile in the cache tree (Default, Profile 1, ...)
$ du -sh ~/Library/Caches/Google/Chrome/* 2>/dev/null | sort -h
# largest items in the profile tree, then inside one profile
$ du -sh ~/Library/Application\ Support/Google/Chrome/* 2>/dev/null | sort -h | tail -15
$ du -sh ~/Library/Application\ Support/Google/Chrome/Default/* 2>/dev/null | sort -h | tail -15
# 'No such file' means that folder doesn't exist on this Mac — skip it

Stay inside Google/Chrome. The parent ~/Library/Caches/Google and ~/Library/Application Support/Google folders can also hold Google’s updater and other Google apps, so measure the Chrome subfolder rather than the whole Google tree.

To match a folder name to a real profile, open chrome://version in each Chrome window. The Profile Path line shows whether that window is Default, Profile 1, Profile 2 and so on. You can open any of these paths in Finder with Go → Go to Folder… (⇧⌘G).

Cache vs cookies vs history vs profile: what each folder is

Sort the names du shows into three groups before you do anything:

  • Cache: regenerates, no sign-in loss. Cache (the HTTP disk cache, with Cache_Data inside) and Code Cache in the profile’s folder under ~/Library/Caches/Google/Chrome; GPUCache inside each profile in Application Support; GrShaderCache and ShaderCache at the top of the Chrome folder. Chrome rebuilds all of these. Pages and graphics just load a little slower the first time.
  • Site data: regenerates, but signs you out or drops offline copies. Cookies, Local Storage, IndexedDB, Session Storage, File System and the Service Worker folder. These hold logins, web-app state and offline data. Clear them per site on purpose, never as a blanket cleanup.
  • Your data: don’t touch. History, Bookmarks, Login Data (saved passwords), Web Data (autofill), Preferences and Secure Preferences, Extensions and their settings. Deleting these files is how people lose passwords that were never synced.

A whole profile folder (Default, Profile 1) contains all three groups mixed together. That is why “delete the Default folder” is never the right fix for disk space.

Preferred: clear Cached images and files in Chrome

Chrome’s own dialog knows which files are cache and which are your data. Use it first:

  1. In Chrome, press ⇧⌘⌫ (Shift-Command-Delete), or open Settings → Privacy and security → Delete browsing data. Older versions call it Clear browsing data.
  2. Set the time range to All time if you want the whole cache gone.
  3. Tick Cached images and files only.
  4. Leave Cookies and other site data, Browsing history, Passwords and Autofill unticked.
  5. Click Delete data.

The dialog works on the profile whose window is in front. If you use several profiles, switch to each one and repeat. With sync on, history you delete is removed on your other devices too, one more reason to tick only the cache box.

Cookies are not a disk-space problem. They are small, and clearing them signs you out of every site and resets per-site settings. Only clear them when that is what you actually want, for example on a shared Mac or to fix one misbehaving site.

Big items that aren’t cache: use Chrome’s own switches

If the Application Support tree is the heavy one, the culprit is often not cache. Each of these has a supported switch inside Chrome:

  • On-device AI model (OptGuideOnDeviceModel at the top of the Chrome folder). Some Chrome features download a local AI model that can take several gigabytes. Google’s supported way to remove it is Settings → System → On-device AI (in some versions under AI Innovations). Turning it off deletes the model and stops re-downloads, and features that rely on it stop working. Deleting the folder by hand may not stop Chrome from fetching it again.
  • Storage from one heavy web app. Large IndexedDB or Service Worker folders usually belong to a few sites (mail, docs, chat, streaming). Open chrome://settings/content/all, sort or search, and delete data only for sites you no longer use. That signs you out of those sites only, which is a deliberate choice rather than a blanket wipe.
  • Extensions you forgot about. Remove them in chrome://extensions. Chrome removes their files and stored settings together, which is cleaner than deleting folders inside Extensions.
  • Profiles you no longer use. Each extra profile has its own cache and site data. Delete one from the profile picker (the card’s menu → Delete) after you have checked its bookmarks and passwords are synced or exported. Don’t delete Profile N folders in Finder.

Finder fallback: quit first, Trash only cache folders

Use this only when the dialog isn’t an option, for example a profile that won’t open or a beta you no longer launch:

  1. Quit Chrome completely with ⌘Q (closing windows isn’t enough). Check that nothing is left running: pgrep -l "Google Chrome" should print nothing. Activity Monitor works too.
  2. In Finder, Go → Go to Folder… and paste ~/Library/Caches/Google/Chrome/Default (or the profile you measured).
  3. Move only Cache and Code Cache to the Trash. For GPU caches, the same applies to GPUCache inside the profile in Application Support and GrShaderCache / ShaderCache at the top of the Chrome folder.
  4. Relaunch Chrome and open a couple of sites. Chrome recreates the folders automatically.
  5. When everything looks normal, empty the Trash. The space comes back only when the Trash is emptied.

Leave everything else in the profile alone, including Cookies, Login Data, History, Preferences and Service Worker. Finder keeps an undo until you empty the Trash, which is why it beats rm here.

If a browser is already uninstalled, its folder under ~/Library/Caches is safe to Trash. Its Application Support folder still holds that browser’s bookmarks and passwords, so export anything you want before removing it.

Edge, Brave, Arc, Vivaldi and other Chromium browsers

Chromium-based browsers use the same layout under their own folder names. Swap the folder into the du commands above, both under ~/Library/Application Support/ and under ~/Library/Caches/:

  • Chrome Beta / Dev / Canary: sibling folders such as Google/Chrome Beta and Google/Chrome Canary, each with its own profiles and cache.
  • Microsoft Edge: Microsoft Edge
  • Brave: BraveSoftware/Brave-Browser
  • Vivaldi: Vivaldi
  • Chromium: Chromium
  • Arc: Arc/User Data
zsh — example: Brave (read only)
$ du -sh ~/Library/Caches/BraveSoftware/Brave-Browser
$ du -sh ~/Library/Application\ Support/BraveSoftware/Brave-Browser/* 2>/dev/null | sort -h | tail -10
# browsers can change folder names between versions — if a path is missing, skip it

The same three groups apply: cache folders regenerate, site data signs you out, profile files are yours. Clear cache from each browser’s own privacy settings first. Most Chromium browsers open their clear-data dialog with ⇧⌘⌫. Safari and Firefox use different layouts and aren’t covered here. Electron apps (chat apps, editors) embed Chromium too, but clear those from each app’s own settings.

What not to do

  • Don’t delete ~/Library/Application Support/Google/Chrome or a whole profile folder like Default. That is a full reset; unsynced passwords and bookmarks go with it.
  • Don’t clear cookies, passwords or history to save space. They are small; losing them costs more than the space is worth.
  • Don’t delete Preferences, Secure Preferences, Login Data or Web Data to “reset” something. Use Chrome’s Reset settings page if you really need a reset.
  • Don’t run sudo rm -rf on browser folders. Nothing here needs admin rights.
  • Don’t touch the whole ~/Library/Caches/Google folder. Stay inside Google/Chrome; the parent folder can hold Google’s updater.
  • Don’t disable SIP or delete anything under /System, /Library or /usr. Browser data lives in your home folder.
  • Don’t delete Docker.raw or VM disk images while hunting System Data. That destroys their contents; see the Docker guide instead.
  • You don’t need Full Disk Access for any of this. If Terminal shows Operation not permitted, use Chrome’s dialog or Finder instead of widening permissions.

Check the result

Re-run the du commands from the measure step. The cache tree should be much smaller right away. If you used Finder, empty the Trash first. System Settings → General → Storage can take a few minutes to recalculate.

Expect the cache to grow back over the next days of browsing. If it climbs back fast, a few heavy sites are usually the reason, and the per-site storage list in chrome://settings/content/all tells you which ones. If Chrome was never large, keep going with the System Data reclaim order, then Xcode caches and Docker disk space on a developer Mac.

Frequently asked questions

Where is the Chrome cache on a Mac?
Chrome keeps its disk cache under ~/Library/Caches/Google/Chrome, with one subfolder per profile (Default, Profile 1, and so on). Your profile data, including cookies, history, bookmarks and saved passwords, lives separately under ~/Library/Application Support/Google/Chrome.
Will clearing the Chrome cache log me out of websites?
Not if you tick only Cached images and files. Sign-ins are stored in cookies and other site data, which is a separate checkbox. Leave it unticked unless you deliberately want to be signed out.
Is it safe to delete ~/Library/Application Support/Google/Chrome?
No. That folder is your Chrome profile: bookmarks, history, saved passwords, cookies, extensions and settings. Deleting it is a full reset. Clear cache from Chrome’s Delete browsing data dialog instead, and only move individual cache subfolders such as Cache or GPUCache by hand.
Why does the Chrome cache come back after I clear it?
Cache is meant to regrow. Chrome stores copies of pages and scripts so sites load faster, and it sizes its cache on its own. Clearing it is a one-time reclaim and a fix for stale pages, not a permanent saving.
What is the large OptGuideOnDeviceModel folder in Chrome?
It holds the on-device AI model some Chrome features use. Google’s supported way to remove it is to turn off On-device AI in Chrome Settings (under System or AI Innovations, depending on version). Chrome then deletes the model and does not download it again while the setting stays off. Deleting the folder by hand may not stop re-downloads.
Does this work for Edge, Brave, Arc and Vivaldi?
Yes, the layout is the same idea. Chromium-based browsers keep profile data under ~/Library/Application Support/<browser folder> and put the disk cache at the matching path under ~/Library/Caches. Clear Cached images and files from each browser’s own privacy settings first.
Do I need sudo, Full Disk Access or to disable SIP to clear browser caches?
No. Browser caches live in your home folder and the browser clears them itself. Do not use sudo rm on browser folders, do not disable System Integrity Protection, and do not delete anything under /System, /Library or /usr.
