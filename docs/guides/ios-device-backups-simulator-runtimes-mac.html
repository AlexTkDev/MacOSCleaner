Free space from iPhone backups and Simulator runtimes on Mac

Review local device backups and unused Xcode Simulator runtimes one item at a time — keep what you still need to restore or boot

Updated 2026-10-12

Two folders often hide tens of gigabytes on a developer Mac, and neither is “cache” in the usual sense. Local iPhone and iPad backups live under ~/Library/Application Support/MobileSync/Backup. Simulator OS images and device data live under ~/Library/Developer/CoreSimulator. The safe loop is: measure with du, review each backup or runtime in Finder or Xcode, then delete only the ones you no longer need. Do not wipe the whole Backup tree, do not rm -rf CoreSimulator, and do not disable SIP.

Two different things people mix up

Local device backups are full restore copies Finder (and older iTunes) makes when you back up an iPhone or iPad to this Mac. Each backup is a folder, often named with a long device identifier (UDID). Losing the only copy means you cannot restore that snapshot.

Simulator runtimes are the iOS / iPadOS (and other) OS images Xcode uses to boot simulators. They are large and regenerable by downloading again from Xcode → Settings → Platforms. They are not your phone’s backup, and they are not the same as Xcode DerivedData or DeviceSupport.

  • Review carefully: ~/Library/Application Support/MobileSync/Backup (local restore copies).
  • Trim with Xcode UI: Simulator runtimes and unused simulator devices under ~/Library/Developer/CoreSimulator.
  • Not this page: iCloud backups (in iCloud, not MobileSync), Time Machine snapshots, and Docker disk images.

Measure first (read only)

Confirm these folders are actually large before you delete anything. On some Macs MobileSync is empty; on others one old encrypted backup is 40 GB by itself.

zsh — measure (read only)
$ du -sh ~/Library/Application\ Support/MobileSync/Backup
$ du -sh ~/Library/Application\ Support/MobileSync/Backup/* 2>/dev/null | sort -h
$ du -sh ~/Library/Developer/CoreSimulator
$ du -sh ~/Library/Developer/CoreSimulator/* 2>/dev/null | sort -h
# 'No such file' means that tree was never created on this Mac — skip it

In Finder, use Go → Go to Folder… (⇧⌘G) and paste the same paths. Get Info on a backup folder shows size on disk. Prefer moving or deleting through Apple’s UI so metadata stays consistent; use Terminal only when you know exactly which folder you mean.

Local iPhone / iPad backups — review, don’t wipe

Preferred path: open Finder, select your device in the sidebar (or connect it), open the device detail, and use Manage Backups…. Delete only backups whose date and device you no longer need. That is safer than guessing UDID folder names by hand.

  • Keep: the newest backup of a device you still own, and any backup you might need for a restore or migration.
  • Safe to remove: backups of phones you sold or wiped years ago, and duplicate older backups of the same device when a newer local or iCloud backup exists.
  • Never: rm -rf ~/Library/Application\ Support/MobileSync/Backup (destroys every local backup at once).

Deleting a Mac-side backup does not erase the phone. It only removes that restore copy from this Mac. If the backup is encrypted, you still need the backup password to restore it later — another reason to decide per backup, not by bulk wipe.

If Terminal shows Operation not permitted on MobileSync, macOS privacy is blocking that app from reading the folder. You do not need to grant Full Disk Access for this job: use Finder’s Manage Backups instead.

Simulator runtimes — Platforms UI first

Quit the Simulator app and Xcode before you remove runtimes. Then open Xcode → Settings → Platforms (on some older Xcode builds this was Components). Delete runtimes for iOS versions you no longer boot. Xcode can download them again later if you need them.

For simulator devices (the fake iPhone entries), use Window → Devices and Simulators and delete devices you never open. That is separate from deleting the OS runtime those devices boot from.

  • Regenerate: CoreSimulator/Caches, and device data/Library/Caches / tmp under each simulator (apps rebuild them).
  • Remove when unused: old runtimes in Platforms, unavailable device records, simulators you never boot.
  • Keep: at least one runtime matching the iOS version you actively test, and any simulator whose installed app state you still need.

Optional Terminal: list, then delete unavailable

After quitting Simulator, these commands are read-only until the last one. Use them to confirm what Platforms already shows:

zsh — simctl
$ xcrun simctl list runtimes
$ xcrun simctl list devices
$ xcrun simctl delete unavailable
# remove one runtime only after you copied its exact identifier from `list runtimes`:
# xcrun simctl runtime delete <runtime-identifier>
# never: rm -rf ~/Library/Developer/CoreSimulator

simctl delete unavailable drops broken device records left after Xcode upgrades. It does not delete healthy simulators you still use. Deleting a runtime by identifier is permanent until you download that OS again from Platforms — read the identifier twice.

What not to do

  • Don’t wipe all of MobileSync/Backup with one command. Delete backups one at a time after you know which device and date they belong to.
  • Don’t rm -rf ~/Library/Developer/CoreSimulator. That can corrupt Xcode’s simulator registry; use Platforms, Devices and Simulators, or simctl instead.
  • Don’t confuse DeviceSupport with backups. DeviceSupport symbols under ~/Library/Developer/Xcode are covered in the Xcode caches guide; they are not restore backups.
  • Don’t disable SIP or delete anything under /System, /Library, or /usr. None of this needs elevated system access.
  • Don’t delete Docker.raw or other VM disks while hunting “backup” space. Those are unrelated and destructive if removed.

Check the result

If you used Finder, empty the Trash — space returns when Trash is emptied, not when the item first moves there. Re-run the du commands above and reopen Xcode once so Platforms and simctl list match what is on disk. If MobileSync and CoreSimulator were already small, the space is elsewhere: continue with the System Data reclaim order, and check Xcode caches and Docker disk space next.

Frequently asked questions

Where are iPhone backups stored on a Mac?
Local Finder (and older iTunes) backups live under ~/Library/Application Support/MobileSync/Backup, usually as folders named with a device UDID. iCloud backups are stored in iCloud, not as that folder on disk.
Is it safe to delete the MobileSync Backup folder?
Do not wipe the whole Backup folder at once. Each subfolder is one local backup. Delete only backups you no longer need, preferably with Finder → Manage Backups, so you keep any restore copy you still care about.
Will deleting a local backup delete photos on my iPhone?
No. Removing a Mac-side backup deletes that restore copy on the Mac. It does not erase the phone. You lose the ability to restore that snapshot unless another backup (local or iCloud) still exists.
What is the difference between DeviceSupport and MobileSync Backup?
DeviceSupport under ~/Library/Developer/Xcode holds symbol files Xcode downloads for connected devices. MobileSync Backup holds full local device backups for restore. They are unrelated; see the Xcode caches guide for DeviceSupport.
Can I delete all Simulator runtimes?
Only if you no longer need to boot any simulator. Keep at least the runtime for the iOS version you actively test. Remove unused runtimes from Xcode → Settings → Platforms, not by deleting random folders under CoreSimulator.
Do I need to disable SIP to free this space?
No. Backups and Simulator data live under your home folder. Do not disable System Integrity Protection and do not delete anything under /System, /Library, or /usr.
