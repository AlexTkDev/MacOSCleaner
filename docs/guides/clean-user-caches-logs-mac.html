What’s safe to delete in ~/Library/Caches and ~/Library/Logs on Mac

How to review user caches and logs one folder at a time, so you get space back without breaking apps or losing settings

Updated 2026-10-08

Sooner or later every Mac guide says “clear your caches”, and every cautious person asks the same thing: which ones, and is it safe? For the two folders in your own Library, ~/Library/Caches and ~/Library/Logs, the honest answer is mostly yes, if you do it in the right order. The safe loop is: measure with du, identify which app owns each big folder, quit that app, clear one folder, and age-filter old logs. Don’t wipe the whole folder at once, don’t touch Application Support, Containers, or system folders, and don’t disable SIP.

What these two folders are

~/Library/Caches is where apps keep data they can rebuild: thumbnails, downloaded web content, compiled shaders, package downloads, update files. Apple’s guidance for developers is that anything in Caches must be safe to lose, and macOS itself may clear it when the disk runs low. ~/Library/Logs holds text logs and crash reports apps write for troubleshooting. Nothing needs them to run.

Both live in your Library (the ~ means your home folder), not the system one. That is what makes them reasonable to review by hand. They sit next to folders that are not disposable, so keep the scope tight:

  • Review: ~/Library/Caches, ~/Library/Logs.
  • Leave alone: ~/Library/Application Support, Containers, Group Containers, Preferences, Keychains, Mail, Messages. These hold real data and settings.
  • Not yours to clear: /System, /Library/Caches, /private/var/folders, and the unified system log. macOS manages them.

Measure first (read only)

Start by finding out whether these folders are even the problem. On many Macs they total a few gigabytes; on a developer Mac or a heavy browser and chat setup they can reach tens.

zsh — measure (read only)
$ du -sh ~/Library/Caches ~/Library/Logs
$ du -sh ~/Library/Caches/* 2>/dev/null | sort -h | tail -20
$ du -sh ~/Library/Logs/* 2>/dev/null | sort -h | tail -10
# 'Operation not permitted' lines are protected folders: skip them

The second command lists the 20 biggest cache folders, largest last. Work from the bottom of that list up; clearing a 3 GB folder is worth the effort, a 40 MB one usually isn’t. If Terminal reports Operation not permitted, that folder is protected by macOS privacy controls. You don’t need to give Terminal Full Disk Access for this job; skip those entries.

Find out which app owns each cache

Most folder names are bundle identifiers in reverse-domain form, like com.apple.Safari or com.microsoft.VSCode. Others are plain tool names such as Homebrew or pip. When the owner isn’t obvious, ask Spotlight which installed app uses that identifier:

zsh — who owns this cache? (read only)
$ mdfind "kMDItemCFBundleIdentifier == 'com.example.app'"
# no result: the app may be gone (a leftover) or the folder belongs to a command-line tool
  • App you use: safe to clear after quitting it. It will rebuild what it needs.
  • App you already deleted: a leftover. Safe to remove; nothing will recreate it.
  • Name you can’t identify at all: leave it for now, or search the name before deciding. Unknown is not the same as junk.

Clear one cache folder at a time

The reliable pattern is quit, move, relaunch, then empty the Trash. Apps can hold cache files open and rewrite them while running, so deleting under a running app wastes effort and can confuse it.

  1. Quit the app that owns the folder (⌘Q, not just closing the window). For menu-bar apps, use their Quit item.
  2. In Finder choose Go → Go to Folder… (⇧⌘G), type ~/Library/Caches, and press Return.
  3. Drag that one folder to the Trash. The Trash keeps it recoverable, but it still uses space until you empty it.
  4. Open the app again and use it normally for a day. Then empty the Trash.

Prefer Terminal? Remove only the exact folder you checked, by full path, with no wildcards. This is permanent, so read the path twice:

zsh — one folder, exact path
$ osascript -e 'quit app "Example"'
$ rm -rf "$HOME/Library/Caches/com.example.app"
# never: rm -rf ~/Library/Caches/* (wipes every app’s cache at once while apps run)

Web browsers are the exception to “just delete the folder”: use the browser’s own clear browsing data or empty caches option, which knows what is cache and what is history, cookies, or saved logins.

Package-manager caches: use the tool’s own cleanup

Developer tools often keep the biggest folders in ~/Library/Caches, and almost all of them ship a cleanup command that knows which files are still in use. Use those first; they are safer than deleting the folder and leave the tool in a consistent state.

zsh — tool-native cleanup
$ brew cleanup --prune=all # Homebrew downloads and old versions
$ npm cache clean --force # npm download cache
$ pip cache purge # pip wheel cache
# run only the ones for tools you actually have installed

For Xcode and Docker, which keep most of their bulk outside ~/Library/Caches, follow the dedicated guides: Xcode caches and Docker disk space. Don’t remove Docker’s or OrbStack’s data by hand from any folder; use their own prune and reset commands.

Prune old logs and crash reports

Logs are simpler than caches: nothing depends on them, so an age filter is a sensible rule. Thirty days keeps anything you might still need for a recent problem. List first, check the output looks like logs, then delete the same set.

zsh — logs older than 30 days
$ find ~/Library/Logs -type f -mtime +30 | wc -l
$ find ~/Library/Logs -type f -mtime +30 | head -30
$ find ~/Library/Logs -type f -mtime +30 -delete

Crash reports live in ~/Library/Logs/DiagnosticReports, and you can read them in the Console app under Crash Reports. Keep the recent ones if an app keeps crashing and you plan to report it; developers find them useful. Otherwise they are safe to remove with everything else above.

Leave the system logs alone. /Library/Logs, /private/var/log, and the unified log that the log command reads are rotated and trimmed by macOS on its own schedule.

What not to do

  • Don’t wipe all of ~/Library/Caches at once with apps running. You lose the ability to tell which app misbehaves afterwards, and some apps crash when their open cache files vanish.
  • Don’t use sudo on cache or log folders, and don’t clear /Library/Caches or /private/var/folders by hand. Reboot if you suspect stale temporary files; macOS cleans them itself.
  • Don’t disable SIP or delete anything under /System. It won’t free meaningful space and it weakens the Mac’s security.
  • Don’t treat caches as a speed fix. Clearing them is a one-time space reclaim or a troubleshooting step. Apps refill them, and that is expected.
  • Don’t delete Docker.raw or VM disk images to “clean caches”. They are not caches, and deleting them destroys containers and images.

Check the result

Empty the Trash, then re-run du -sh ~/Library/Caches ~/Library/Logs and compare. If the number dropped but Storage in System Settings barely moved, local Time Machine snapshots may still hold the deleted data for a while, and Settings can take some time to recalculate. If these folders were small to begin with, the space is somewhere else: work through the System Data reclaim order, which starts with the folders that are usually much bigger on a developer Mac.

Frequently asked questions

Is it safe to delete ~/Library/Caches on a Mac?
Mostly, yes, because apps are supposed to keep only data they can rebuild there. The safe way is one folder at a time: quit the app that owns it, move that folder to the Trash, relaunch the app, and empty the Trash once it works. Avoid deleting the whole folder in one go while apps are running.
Will clearing caches make my Mac faster?
Usually not. Caches exist to make apps faster, so an app may feel a little slower right after you clear its cache while it rebuilds it. Clear a cache to get disk space back or to fix an app that misbehaves, not as routine speed maintenance.
Why did the cache come back after I deleted it?
That is normal. Apps recreate their caches as you use them. If one cache keeps growing back to many gigabytes, look for a cache-size or offline-storage setting in that app, or use the tool’s own cleanup command, such as brew cleanup for Homebrew.
Can I delete everything in ~/Library/Logs?
Log files there are written for troubleshooting and are not needed for apps to run. Removing files older than about 30 days is a reasonable default. Keep recent crash reports if you are chasing a bug or want to send them to a developer.
What about /Library/Caches, /System/Library/Caches, and /private/var/folders?
Leave them alone. /System is protected by System Integrity Protection, /Library/Caches is shared by every user and system services, and /private/var/folders holds per-user temporary files that macOS manages itself. Clearing them by hand with sudo can break things and rarely frees much.
Will deleting caches sign me out of apps or delete my settings?
Settings live in ~/Library/Preferences and app data in ~/Library/Application Support or ~/Library/Containers, so clearing a cache normally keeps both. A few apps may ask you to sign in again or re-download offline content, which is one more reason to clear one app at a time.
