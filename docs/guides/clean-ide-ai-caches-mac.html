How to clean Cursor, VS Code, JetBrains & AI caches on Mac

Quit the tools, measure with du, clear regenerable caches — manage local models with their own CLIs

Updated 2026-09-17

Editors and AI assistants cache indexes, Electron/Chromium data, extension VSIXs, language-server artifacts, and sometimes multi-gigabyte local models under your home folder. None of that is your git repo. The safe loop is: quit the apps, measure with du, then move regenerable caches to Trash. Settings, API configs, conversation stores, and model blobs need a different rule: review carefully or use the vendor CLI. Do not disable SIP. Do not delete under /System or /usr.

Quit first

Fully quit Cursor, Visual Studio Code, Windsurf, Zed, JetBrains IDEs (IntelliJ, WebStorm, PyCharm, and siblings), Claude Desktop, Ollama, and any visible helper processes. Cache and index files stay open while those processes run. Cleaning with the app still running can fail, look like “nothing happened,” or leave a half-written session.

In Activity Monitor, confirm no leftover Code Helper, Cursor Helper, or JetBrains daemon is still holding files.

Measure with du before deleting

Allocated size is what Storage cares about. Run these in Terminal after quitting the tools, then decide what is worth reclaiming:

zsh — measure IDE & AI trees
# Electron / VS Code family
$ du -sh ~/Library/Application\ Support/Cursor ~/Library/Caches/Cursor ~/.cursor 2>/dev/null
$ du -sh ~/Library/Application\ Support/Code ~/Library/Caches/com.microsoft.VSCode ~/.vscode 2>/dev/null
# JetBrains
$ du -sh ~/Library/Caches/JetBrains ~/Library/Logs/JetBrains ~/Library/Application\ Support/JetBrains 2>/dev/null
# Claude / Ollama / Hugging Face (paths vary by install)
$ du -sh ~/Library/Application\ Support/Claude ~/.claude ~/Library/Caches/claude-cli-nodejs 2>/dev/null
$ du -sh ~/.ollama ~/Library/Caches/com.anthropic.claudefordesktop ~/.cache/huggingface 2>/dev/null

In Finder, use Go → Go to Folder… (⇧⌘G) and paste the same paths. Prefer moving items to Trash over rm -rf so you can restore a mistake.

Cursor, VS Code, Windsurf — regenerable vs keep

Cursor and VS Code (and similar Electron editors) split data across Application Support, Caches, and a home extensions folder. After quitting, these are usually safe to clear because the app recreates them:

  • …/Cache, …/CachedData, …/CachedExtensionVSIXs, …/Code Cache, …/GPUCache, …/logs
  • Old CachedData subfolders left behind after version upgrades
  • ~/Library/Caches/Cursor and ~/Library/Caches/com.microsoft.VSCode

Treat these as review-before-delete (not automatic wipe):

  • User/workspaceStorage — per-project extension state and indexes; clearing it resets UI/state for those workspaces, not your source trees.
  • User/globalStorage and User/settings.json — settings and extension global data; leave alone unless you intend a reset.
  • ~/.cursor/extensions and ~/.vscode/extensions — installed extensions; remove unused ones deliberately rather than deleting the whole tree.

If you run both Cursor and VS Code, you may carry duplicate extensions. Prune by name in each extensions folder after you confirm you no longer need that pack.

JetBrains caches and leftover versions

IntelliJ-based IDEs store regenerable caches under ~/Library/Caches/JetBrains/ and logs under ~/Library/Logs/JetBrains/. After quitting the IDE, those trees are safe to move to Trash. Indexes rebuild on the next open (slower first launch).

Upgrades often leave old version folders under Application Support and Caches. Keep the folder matching the version you still run; remove abandoned version directories only when you recognize them as leftovers from an uninstall or major upgrade. Do not delete project sources or the .idea folder inside a git repo as part of “cache cleanup.”

JetBrains Toolbox can also remove unused IDE installs from its own UI — prefer that for whole-product uninstalls.

Claude, Ollama, Hugging Face — caches vs models

Local AI tools mix small regenerable caches with large model and session stores. Treat them differently.

  • Usually regenerable: ~/Library/Caches/com.anthropic.claudefordesktop, ~/Library/Caches/claude-cli-nodejs, UI caches, and similar Electron cache trees after quitting.
  • Review carefully: ~/.claude/ project/session data, Claude Desktop Application Support (including any VM/bundle folders), and config files that may hold MCP or API settings.
  • Models — use the CLI: Ollama models live under ~/.ollama with content-addressed blobs. List and remove with the official commands, not by deleting hashed blob files:
zsh — Ollama model hygiene
$ ollama list
$ ollama rm MODEL_NAME
# do not rm -rf ~/.ollama/models/blobs — blobs are shared

For Hugging Face caches under ~/.cache/huggingface, prefer the Hugging Face CLI cache list/remove flow (or the Hub docs for your installed version) so shared snapshots stay consistent. Deleting blob trees by hand can orphan models the same way Ollama does.

Regenerate vs keep checklist

  • Regenerate: IDE Cache / CachedData / CachedExtensionVSIXs / logs, JetBrains Caches and Logs, Claude/Electron UI caches after quit.
  • Review: workspaceStorage, unused extensions, abandoned JetBrains version folders, Claude session/project folders, large Application Support trees you recognize.
  • CLI-managed: Ollama models (ollama rm), Hugging Face cache entries via the Hub/CLI tools you already use.
  • Keep: settings.json and intentional configs, API/MCP config you still need, project source trees, Keychain items.
  • Never: SIP off, deletes under /System or /usr, blind rm -rf ~/.ollama/models/blobs, wiping Docker.raw “for free space,” or deleting critical system paths.

After Trash, empty Trash only when you are sure. Space returns when Trash is emptied, not when files first move there. Then reopen each editor once so indexes and caches come back.

Frequently asked questions

Is it safe to delete Cursor or VS Code cache folders on Mac?
Yes for regenerable caches (Cache, CachedData, CachedExtensionVSIXs, logs) after quitting the app. Settings under User/ and installed extensions are separate. Clearing workspaceStorage resets per-project UI state, not your source code.
How do I free space from Ollama models on Mac?
List models with ollama list, then remove unused ones with ollama rm MODEL. Do not delete hashed files under ~/.ollama/models/blobs by hand — blobs are shared and the CLI knows which are still referenced.
Do I need to disable SIP to clean IDE or AI caches?
No. These caches live under your home folder. Do not disable SIP and do not delete anything under /System or /usr.
