How to reclaim Homebrew disk space on Mac safely

Measure cache and prefix, dry-run brew cleanup, prune old bottles, uninstall unused formulae — leave the Cellar to brew

Updated 2026-09-28

Homebrew keeps downloaded bottles and older keg versions so installs and upgrades can reuse local files. After months of brew upgrade churn, that cache and leftover kegs can look like “mystery” disk use under Storage. The safe loop is: measure the download cache and the Homebrew prefix, preview with brew cleanup --dry-run, then let Homebrew remove stale downloads and old versions. Prefer brew uninstall / brew autoremove over deleting Cellar folders by hand. Do not disable SIP. Do not wipe /opt/homebrew or /usr/local wholesale while packages are still installed.

Measure cache vs installed kegs

Two different trees matter. The download cache holds bottle and source archives you can usually prune. The prefix (Cellar, Caskroom, linked bins) holds software you still use — reclaim that only by uninstalling packages, not by deleting folders at random.

zsh — measure Homebrew disk use
$ brew --cache
$ du -sh "$(brew --cache)"
$ brew --prefix
$ du -sh "$(brew --prefix)"
# common Apple Silicon layout (confirm with brew --prefix first)
$ du -sh /opt/homebrew/Cellar /opt/homebrew/Caskroom 2>/dev/null

On most Macs, brew --cache prints ~/Library/Caches/Homebrew. Apple Silicon installs usually live under /opt/homebrew; older Intel installs often use /usr/local. Always trust brew --prefix and brew --cache over a guessed path.

Dry-run brew cleanup first

brew cleanup removes stale lock files, outdated downloads, and old versions of installed formulae. By default it targets downloads older than about 120 days (adjustable with HOMEBREW_CLEANUP_MAX_AGE_DAYS). Preview before you commit:

zsh — preview cleanup
$ brew cleanup --dry-run
# same preview with short flag
$ brew cleanup -n

If the dry-run list looks right, run brew cleanup with no flags. Do not run cleanup while another brew install, brew upgrade, or brew uninstall is already changing the prefix. Homebrew also runs cleanup periodically after upgrades unless you set HOMEBREW_NO_INSTALL_CLEANUP=1 — a large cache often means you disabled auto-cleanup or you accumulate downloads faster than the default age window.

When standard cleanup is not enough

If du still shows a large cache after a normal cleanup, prune older downloads more aggressively — only when re-downloading bottles later is acceptable (you have network, and offline reinstall of the same bottles is not required).

zsh — prune cache (after dry-run)
$ brew cleanup --prune=all --dry-run
$ brew cleanup --prune=all
# optional: scrub cache downloads even for current versions
# (installed kegs stay; bottles may need re-download later)
$ brew cleanup -s

--prune=all removes cache files that the default age window may keep for reuse. brew cleanup -s scrubs more of the cache, including downloads for current versions, while still leaving installed formulae in place. Official docs also note that deleting the entire cache directory with rm -rf "$(brew --cache)" is possible for a full wipe of downloads — prefer the brew cleanup flags first so keg cleanup and Homebrew’s own rules stay consistent.

Unused packages vs cache

Cache cleanup does not uninstall tools you installed and forgot about. Those live in the Cellar / Caskroom and only shrink when you remove the package through Homebrew:

zsh — unused formulae
# formulae you installed that nothing else depends on
$ brew leaves
# remove orphaned dependencies left after uninstalls
$ brew autoremove --dry-run
$ brew autoremove
# uninstall a specific tool you no longer need
$ brew uninstall FORMULA_OR_CASK
$ brew cleanup

Review brew leaves before mass uninstalls — “leaf” only means nothing else in Homebrew depends on it; you may still use that CLI every day. Prefer named brew uninstall over deleting directories under Cellar or Caskroom in Finder.

What to leave alone

  • Safe reclaim targets: download cache via brew cleanup / --prune, old keg versions cleanup removes, packages you deliberately uninstall, orphaned deps via brew autoremove.
  • Keep until you uninstall the package: current Cellar kegs, Caskroom apps you still use, linked binaries under the prefix.
  • Never as “Homebrew cleanup”: wiping all of /opt/homebrew or /usr/local while software is installed, deleting /System or /usr, disabling SIP, or treating Docker.raw / Xcode DerivedData as Homebrew cache.
  • If Storage is still tight after brew work: measure developer trees next — Xcode caches, Docker disk space, and System Data reclaim order — those often dwarf the bottle cache.

Frequently asked questions

Where does Homebrew store its download cache on Mac?
Run brew --cache. On most Macs that path is ~/Library/Caches/Homebrew. Measure it with du -sh "$(brew --cache)" before deciding how aggressive to prune.
Is it safe to delete ~/Library/Caches/Homebrew?
Prefer brew cleanup (dry-run first). Prune with --prune=all or scrub with -s when you accept re-downloads. Do not delete the Cellar or the whole Homebrew prefix while packages are still installed, and do not run cleanup during another brew install/upgrade.
Do I need to disable SIP to clean Homebrew?
No. The download cache lives under your home folder, and the default Apple Silicon prefix is /opt/homebrew. Do not disable SIP and do not delete anything under /System or /usr to free Homebrew space.
